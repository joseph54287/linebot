# LINE 收據影像代墊登記設計

## 目標

員工在 LINE Bot 個人聊天室上傳一張發票或收據，並於 30 分鐘內輸入「代墊」後，系統自動從圖片辨識支出資料、檢查完整性並顯示確認圖卡。員工確認後才寫入 Google Sheet。

## 登記單位

- 一張收據或發票建立一筆支出資料。
- 金額使用單據上的應付總額或實付總額，不把各明細重複加總。
- 多個品項合併寫入「消費項目」，以頓號分隔。
- 一次只處理一張圖片；多張單據須分開登記，避免收據與金額配對錯誤。

## 觸發方式

以下兩種順序都支援：

1. 先上傳圖片，再於 30 分鐘內輸入 `代墊`。
2. 先輸入 `代墊`，Bot 提示上傳圖片，再於 30 分鐘內上傳。

只有已登記的內部員工能在 Bot 個人聊天室使用。群組圖片不觸發支出辨識。

## 圖片辨識

採用 Gemini 圖像理解服務，輸出固定 JSON 欄位：

- `documentType`：發票、電子發票、收據或其他。
- `merchantName`：商家名稱。
- `date`：消費日期，格式 `YYYY-MM-DD`。
- `items`：品項名稱陣列。
- `totalAmount`：整張單據總額。
- `invoiceNumber`：發票號碼，可空白。
- `taxId`：統一編號，可空白。
- `hasBusinessTaxId`：是否含公司統編。
- `currency`：預設 TWD。
- `confidence`：整體辨識信心，0 至 1。
- `warnings`：模糊、遮擋、裁切或金額不一致等警告。

AI 只負責辨識圖片；後端必須再次驗證日期、金額、型別與允許值。

## 自動補值與分類

- 支出人：依 LINE User ID 自動帶入。
- 付款時程：預設 `已支出`。
- 是否已領款：預設 `否`。
- 收據：使用本次上傳的原圖。
- 消費項目：品項合併；沒有明細時使用商家名稱。
- 分類：沿用既有關鍵字分類規則；無法安全判斷時列為缺漏。
- 專案名稱：單據通常無法得知，若沒有現有對話資訊則一次補問。

## 完整性與誤判防護

必要欄位為日期、消費項目、總額、支出人、分類及專案名稱。

- 總額不存在、出現多個互相衝突的總額，或總額小於等於 0：不得確認送出。
- 圖片模糊、裁切或非單據：提示重新拍攝，不建立支出暫存。
- 信心低於 0.75：顯示辨識結果與警告，要求員工確認或修改。
- 日期無法辨識：一次列入缺漏，不自動使用上傳日期。
- 不能把發票號碼、統編、交易序號或年份誤判成金額。
- 未按 `確認送出` 不得寫入 Google Sheet。

## 確認與修改

辨識完成後顯示一張確認圖卡，包含：

- 單據類型、商家、日期、專案、品項、總額、分類、支出人、統編狀態。
- `確認送出`：上傳原圖到 Drive 並寫入 Google Sheet。
- `修改`：員工以一句話修改，例如 `專案改成 TOYOTA，金額改成 850`。
- `重新拍攝`：清除舊圖，等待新圖。
- `取消`：清除本次資料。

只有缺少專案或其他必要欄位時，Bot 一次列出全部缺漏，不逐題詢問。

## 狀態與資料流程

1. LINE Webhook 下載圖片並建立 30 分鐘暫存。
2. 收到 `代墊` 後，將圖片交給 Gemini 分析。
3. 後端驗證 JSON 並轉換成既有支出欄位。
4. 資料不足時一次補問；完整時顯示確認圖卡。
5. 員工確認後呼叫既有 Apps Script API。
6. Apps Script 將圖片存入 Drive 並在 Sheet 新增一列。
7. 寫入成功才回報完成；失敗保留暫存供重試。

## 安全與成本

- Gemini API Key 只存於 Render Secret，不寫入 GitHub、訊息或日誌。
- 只傳送本次員工主動上傳的單據圖片，不存入第三方測試工具。
- 圖片辨識逾時或服務失敗時保留圖片，提示稍後重試。
- 影像服務未設定時，既有文字快速登記仍可使用。

## 測試與驗收

- 支援「先圖後代墊」與「先代墊後圖」。
- 正確辨識台灣電子發票、一般發票與手寫收據。
- 多品項合併成一筆，總額不重複計算。
- 模糊圖片、非收據圖片及多個衝突金額不會直接寫入。
- 發票號碼、統編與日期不會被當成支出金額。
- 缺少專案時只補問專案。
- 修改後重新驗證並更新確認圖卡。
- 重複點擊確認不新增重複列。
- Gemini、LINE、Drive 或 Apps Script 失敗時不回報成功。
- 所有自動測試通過，Render 健康檢查顯示影像辨識已設定。
