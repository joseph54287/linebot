# LINE 收據辨識改善與近期專案選擇設計

## 目標

改善真實發票或收據被誤判為非單據的問題，並為後續專案系統串接預留穩定介面。員工上傳單據並輸入「代墊」後，Bot 應優先完成欄位擷取；缺少專案時，顯示近期且尚未結案的專案選項，讓員工直接點選。

## 收據辨識策略

Gemini 第一輪只負責擷取欄位與描述影像類型，不再讓單一 `isReceipt` 布林值決定整筆流程是否失敗。後端以多個訊號判斷是否可繼續：

- 必須辨識出大於 0 的合理總額。
- 日期、商家名稱或品項至少成功辨識一項。
- 符合以上條件時，即使模型把 `isReceipt` 判為 `false`，仍視為可處理單據。
- 發票號碼、統編、年份與交易序號不得當作總額。

第一輪缺少合理總額或有效訊號時，系統以同一張圖片自動執行第二輪辨識。第二輪提示詞聚焦於 OCR 文字、應付／實付總額及日期，並把兩輪結果依欄位完整度合併。

只有圖片明確為人物、風景、聊天截圖等非文件內容，且兩輪都沒有金額或單據特徵時，才回覆圖片不是可辨識單據。若看起來像文件但仍抓不到總額，改回覆「無法辨識總額，請補充金額或重新拍攝」，不再錯誤宣告不是收據。

## 專案資料來源

建立獨立的專案資料來源介面，代墊流程只依賴統一格式，不綁死未來專案系統的品牌或 API：

- `id`：專案唯一識別碼。
- `name`：顯示與寫入表單的專案名稱。
- `status`：專案狀態。
- `updatedAt`：最後更新時間。
- `aliases`：專案別名或客戶關鍵字，可空白。

正式來源預留 `PROJECT_API_URL` 與 `PROJECT_API_KEY` 環境變數。API 尚未設定、逾時或資料格式錯誤時，不中斷代墊登記，改由員工直接輸入專案名稱。

## 近期未結案專案規則

- 排除狀態為 `closed`、`completed`、`cancelled`、`archived`，並兼容常見中文結案狀態。
- 只保留最近 90 天建立或更新的專案。
- 最多顯示 10 個選項，避免 LINE 圖卡過長。
- 依收據文字、商家、品項與員工補充內容的關鍵字相關性排序；沒有明顯關聯時，以最後更新時間由新到舊排序。
- 例如內容出現 `PJR`，名稱或別名含 `PJR` 的未結案專案優先顯示。

## LINE 操作流程

1. 員工上傳單據並輸入「代墊」。
2. 系統執行第一輪辨識；資料不足時自動執行第二輪並合併。
3. 後端驗證日期、金額、品項與分類。
4. 專案名稱缺漏時，讀取近期未結案專案並顯示可點選圖卡。
5. 員工點選專案後，系統以暫存中的專案 ID 取回名稱，避免把長名稱直接放入 postback。
6. 圖卡保留「其他／自行輸入」選項；專案 API 無法使用時直接提示輸入名稱。
7. 所有必要欄位完整後顯示既有確認圖卡；員工按「確認送出」後，Bot 才下載 LINE 原始收據並送交 Apps Script。
8. Apps Script 將收據存入公司 Google Drive，以日期、員工、專案及金額產生可追蹤的檔名，再把 Drive 檔案連結與代墊欄位寫入公司 Google Form 所連動的回覆試算表同一列。

專案選項只存於該員工目前的代墊暫存，30 分鐘後與代墊資料一起失效，避免不同員工或不同單據互相套用。

## 錯誤處理與紀錄

- Gemini 第一輪失敗時仍嘗試第二輪；兩輪皆因服務錯誤失敗時保留暫存並提示稍後重試。
- 專案 API 最多等待短時間，失敗即降級為手動輸入，不阻塞收據登記。
- 日誌只記錄影像類型、是否有金額／日期、品項數量、信心值、是否使用第二輪及專案候選數量；不記錄圖片、API Key、完整收據文字或個資。
- Apps Script 寫入失敗時不得回覆成功，並保留資料供員工重試。
- Drive 收據上傳或表單回覆資料任一寫入失敗時，整筆不得回覆成功；重試時使用同一筆交易識別碼，避免重複建立附件或資料列。

## 設定與相容性

- 既有 `GEMINI_API_KEY`、`RECEIPT_VISION_MODEL`、文字代墊及圖片代墊流程維持相容。
- 新增的專案 API 環境變數皆為選填；尚未串接專案系統時仍可部署。
- 專案 API 金鑰只存於 Render Secret，不提交 GitHub。
- 延用現有公司 Google Form 的欄位方向；Apps Script 直接寫入該表單所連動的回覆試算表。Google Form 的檔案上傳題不接受 Bot 代替使用者提交，因此附件欄位保存 Google Drive 收據連結，確保同一列可直接開啟原圖。
- 若目前回覆試算表尚無「收據附件」或等效欄位，Apps Script 只新增該欄位，不變更其他既有欄位與歷史資料。

## 測試與驗收

- `isReceipt=false` 但有合理總額與日期、商家或品項時，仍能進入代墊流程。
- 第一輪缺少總額，第二輪找到總額時，能合併結果並繼續。
- 兩輪都缺少總額但像文件時，要求補充金額或重拍，不回覆「不像收據」。
- 明確非單據圖片且沒有任何有效訊號時才拒絕。
- 未結案狀態、90 天範圍、相關性排序及最多 10 筆規則正確。
- 點選專案後能填入專案名稱並顯示確認圖卡。
- 專案 API 未設定或失敗時可改用手動輸入，既有流程不受影響。
- 確認送出後，LINE 原始收據成功存入公司 Drive，回覆試算表同一列包含可開啟的附件連結。
- Drive 或試算表任一步驟失敗時不回報成功；重試不產生重複附件或重複資料列。
- 所有既有測試與新增測試通過，Render 健康檢查正常。
